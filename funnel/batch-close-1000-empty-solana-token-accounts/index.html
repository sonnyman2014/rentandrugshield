Solana's 1,232-Byte MTU & Compute Unit Math for Mass ATA Closures

Why can't a wallet close 1,000 empty token accounts inside a single Solana transaction? The bottleneck is not compute units—each native Tokenkeg 0x09 CloseAccount instruction consumes roughly 2,900 CUs, well inside Solana's 200,000 default / 1,400,000 max CU ceiling. Instead, the hard ceiling is Solana's IPv6-safe 1,232-byte serialized transaction packet limit. Every unique empty ATA pubkey requires a 32-byte account entry in the message header (Address Lookup Tables cannot compress writable accounts initialized dynamically if not pre-indexed on-chain!).

After reserving 64 bytes for the Ed25519 signature, 32 bytes for the recent blockhash, 32 bytes for the owner pubkey, and 32 bytes for the SPL Token program ID, a standard legacy or v0 message cleanly fits 22 to 24 unique writable ATA pubkeys plus compact 4-byte CloseAccount instruction descriptors. Closing 1,000 ATAs therefore executes across ~42 deterministic sub-transactions costing barely 0.00021 SOL in total network base fees.
