1. Why Empty SPL Token Accounts Lock SOL After Every Trade

Solana enforces state rent-exemption proportional to byte storage. Under the canonical SPL Token program (TokenkegQfeZyiNwAJbNbGKPFXCWuBvf9Ss623VQ5DA), each token mint requires a dedicated Associated Token Account derived deterministically from [wallet_pubkey, token_program_id, mint_pubkey]. Creating that 165-byte account plus its 128-byte account header requires exactly 2,039,280 lamports. DEX routers execute Swap instructions that reduce tokenAmount.amount to 0 on exit, yet routers rarely append CloseAccount so repeat buys do not re-pay rent. Active traders routinely accumulate 100 to 5,000+ zero-balance ATAs locking 0.20 SOL to 10+ SOL.

2. How Native Instruction 0x09 (CloseAccount) Safely Refunds Lamports

Native SPL Token instruction index 9 (0x09 CloseAccount) verifies three strict runtime invariants inside the Solana BPF runtime: (a) the account's raw token balance must equal zero (amount == 0), (b) the account state must not be frozen (state != frozen), and (c) the transaction signer must match the account owner or designated closeAuthority. When all three invariants hold, the runtime zeroes the account data, assigns ownership back to the System Program, and credits 100% of the lamports directly to your wallet in the exact same atomic slot.
